# ADR-0002：多角色对话采用 NDJSON 流式协议

- 状态：已采纳
- 日期：2026-08-11

## 背景

对话曾要求模型输出完整 JSON 数组或 `responses` 包装对象。模型偶尔直接输出纯文本；即使结构正确，部分 HTTP 客户端也可能缓冲完整响应，导致 UI 在结束时一次性显示。完整数组还会让尾部截断破坏整份回复。

## 决策

多角色对话的模型输出采用 NDJSON：每行一个完整 JSON 对象，必填 `speaker` 和 `message`，可选 `inner_thought`。解析器在当前行尚未闭合时增量投影 `message`，最终解析按完整行提交，并兼容旧数组与包装对象。

模型响应由平台流式 HTTP 接口直接消费，服务端和本地 SSE 及时 flush。第一个可见台词 delta 立即进入 UI，后续只做短时间帧级合批。

## 结果

优点：

- 已完成的角色行不受后续截断影响；
- 可以在对象闭合前显示台词内容；
- 每行结构独立，错误定位和重试更清晰；
- 避免“完整数组结束后才显示”。

代价：

- NDJSON 整体不是单个合法 JSON 对象，不能使用 `response_format=json_object`；
- 解析器需要同时维护增量投影和最终严格校验；
- provider 可能一次返回多个字符，不能保证严格逐字显示。

## 约束

不得通过人为延时伪造打字速度。其他只返回单个对象的模型任务继续使用 provider 原生 JSON 约束。
