# ADR-0005：羁绊数值由模型裁决、后台派生累积

- 状态：提议（待评审，随 `docs/design/bond-arbiter.md` 一并评审）
- 日期：2026-11-18

## 背景

当前角色对话是「单机 + 模型」：没有真实其他玩家、没有联网社区，关系数据（`trust/affection/hostility/ambiguity`）只能靠蒸馏结果与既有派生机制维护。用户希望在闲聊之上看到一条随时间累积的养成线（角色对「我」的好感进展、阈值反馈），且不能因此增加回复延迟或失控的 token 成本。

## 决策

1. **由模型裁决增量，不由客户端或规则写死**：一次裁决输入本轮用户输入 + 各角色本轮台词 + 当前羁绊值 + 角色资料摘要，输出单对象 `{"deltas":[...]}`；单次增量绝对值上限 3，最终 `clamp(0..10)`。
2. **裁决是单对象 JSON 任务**：使用 provider 原生 `response_format=json_object` 约束 + 严格解析校验兜底，不与对话主协议 NDJSON 混用。
3. **挂在后台派生批处理**：复用 `DialogueService.drainBackgroundPostTurns`，在提交回复之后执行，不占用回复关键路径；`every_n` 的「攒够 N 轮才裁一次」由批合并天然支持。
4. **默认关闭**：`bond_arbiter_enabled` 默认 `false`、`mode` 默认 `manual`，用户显式开启后才产生模型调用；`settle` 与 `both` 留 v2。
5. **双层落盘**：run 级写 relations 文件的 `{role}::我` 约定配对键（跨会话累积），session 级写 `bond_progress`（即时反馈 + 幂等去重）；`{role}::我` 默认不进入角色关系图与冲突/派系统计。
6. **不引入任何在线依赖**：无排行榜、无其他玩家、无云端同步；唯一外部依赖仍是模型本身。

## 结果

优点：

- 养成线有可解释的数值来源（模型给出的 `reason` + 增量），不是随机数；
- 默认零自动驾驶成本，用户主动「恳谈」才花钱；
- 复用既有 relations 与后台派生机制，不新造存储范式；
- 裁决失败不影响对话可用性。

代价：

- 多一个模型任务需要维护提示词与解析契约（`prompts/**` 与 Android assets 双份同步）；
- `{role}::我` 需要在 relations、关系路由、关系图侧都做识别与排除，否则污染角色间关系；
- `every_n` 会带来后台模型调用的累积成本，需要 `every_n` 上限（2..20）兜底。

## 约束

- 裁决不得阻塞 `commitTurn` 与 `complete` SSE；失败时后台静默跳过，手动接口返回错误但可重试。
- 同一 `turn_id` / 同一 `operation_id` 重放不得重复累加。
- 羁绊数值不进入 API 密钥、日志明文或提示词之外的任何密钥路径。
